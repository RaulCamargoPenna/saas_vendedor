# SaaS Vendedor structured producer — draft, not activated

Contract: VPS Control ADR 0003 (`host_agent/structured_events.py`). This branch does **not** change the host collector, its bindings, the production checkout, or the deployed Compose stack. No Docker stdout/stderr is read or emitted as events. Uninstrumented deployments remain absent from the VPS Control event panel.

The image healthcheck runs `python manage.py publish_ready_event`: local HTTP GET to `/saas/` (fixed Host, 3-second timeout, no redirects) and database `SELECT 1` must both succeed. Only then, if `SAAS_EVENT_SOURCE_DIR` is explicitly set, it publishes a single version-1 `app.ready` JSONL event with integer UTC timestamp. Without opt-in it remains a readiness probe and writes no events. A failing probe or publication fails the healthcheck without printing exception details. This is **not** a statement that the public reverse proxy, all external dependencies, or the release bookkeeping succeeded. The new image uses UID/GID 10001:10001, with `/app/staticfiles` writable for collectstatic; validate deployment compatibility before merge.

The producer uses a fixed code (no request-supplied event payload), absolute no-symlink directory walk, exact 0700 directory and 0600 regular one-link file owned by its own UID/GID, a directory flock across inspection and publication, fresh closed previous-event validation, one ASCII JSONL line, 8192-byte file / 256-byte line reader-compatible bounds, private unique temporary, file fsync, exact nanosecond mtime verification, atomic replace, directory fsync, and rejects older/equal capture times. Failed directory fsync after replace may leave the new file visible; clock rollback blocks publication until time catches up. This does **not** authenticate a producer by metadata alone.

`job.succeeded` is deliberately rejected: the tracked checkout has no durable job-completion integration and the production-only untracked deploy/rollback scripts are not modified by this branch. Do not emit success merely for command invocation, health, HTTP 200, migration start, or container restart. A later separately reviewed, test-first hook may emit it only after a concrete job's durable success/bookkeeping and with no free-text, SHA, user, argument, tool output or error. Do not add a public trigger for this command.

## Operator gates before activation (not performed here)

1. Review image non-root UID/GID compatibility, staticfiles ownership, current deploy/rollback behavior and healthcheck timing in a disposable staging stack with an isolated DB. This repo's `compose.yml` has no healthcheck and deploy currently uses external HTTPS curl; do not equate the two signals. Test migration/collectstatic and external readiness after the image change.
2. Provision a **dedicated** producer host directory and bind mount for SaaS Vendedor, owned by the host-mapped UID/GID of container UID/GID 10001:10001, mode 0700, with no other app/collector writer and no alias to another source. Verify actual UID mapping, non-root runtime, mount topology, exact nano-mtime behavior and denies for a different app UID. The collector must have explicitly reviewed read access independent of any web app; never give the app a Docker socket or host collector config. A directory owned by container root or shared with another application is **not** acceptable.
3. Provide `SAAS_EVENT_SOURCE_DIR` and its corresponding host mount only through a separately reviewed, opt-in deployment overlay whose deploy **and rollback** paths preserve the selection; avoid Compose auto-creation of missing host paths. The current Compose definitions do not mount a source. Do not set the variable before provisioning.
4. Configure the host-only collector source binding to the exact current `(project, name, 64-hex container_id)` from a fresh private inventory snapshot; verify directory **and event-file** identity uniqueness. Container recreation requires explicit ID rotation and release gating; recycled names cannot inherit a prior binding. Validate collector timer/snapshot and web API in staging, including stale/invalid source revocation. No HTTP input may control a source path, identity, code, timestamp or count.
5. Before merge, independent security review, synthetic malicious-source tests, cross-process writer/reader races on target filesystem, build and healthcheck in staging, and release/rollback failure rehearsal are required. Merging master auto-triggers the production deploy workflow, so **keep this PR draft** until these gates pass and maintenance is authorized. No production action was taken.
